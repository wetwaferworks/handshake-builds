HandshakeOS v5.8 for the Anbernic RG35XX 2024 — flash instructions
==================================================================
Image: v5.8. v5.7 remains the known-good fallback; do not overwrite it.

This image is for a SPARE microSD card (TF1). Do not overwrite the
stock card.

Files
-----
  handshakeos-rg35xx-2024-v5.8.img.zst   compressed image — copy this first
  handshakeos-rg35xx-2024-v5.8.img       raw disk image, 134,217,728 bytes (128 MiB)

SHA-256 values are in SHA256SUMS next to the image (and printed by the
pack script). Verify both the .zst and the raw .img after decompressing.

Decompress (PowerShell or WSL, in this folder)
----------------------------------------------
  Get-FileHash .\handshakeos-rg35xx-2024-v5.8.img.zst -Algorithm SHA256
  zstd -d -f .\handshakeos-rg35xx-2024-v5.8.img.zst
  Get-FileHash .\handshakeos-rg35xx-2024-v5.8.img -Algorithm SHA256
The raw file must be exactly 134,217,728 bytes.

Flash
-----
1. Open Rufus, Raspberry Pi Imager, or balenaEtcher.
2. Select handshakeos-rg35xx-2024-v5.8.img (the raw file, not the .zst).
3. Select the SPARE microSD card. Triple-check the drive letter.
4. Write the image. Eject the card safely.
5. Plug the card into the RG35XX 2024 (TF1 slot).
6. Power on. U-Boot loads /boot.scr and boots the v5.8 kernel and initramfs.

On first boot, leftover space after this partition is turned into a
second FAT32 partition labelled HSROMS (same as v5.7).

Kernel
------
Linux 7.3.5 + ROCKNIX, starting from the same device source/config that
produced the v5.2 / v3-audio Image.gz c206e1bc…, with Handshake patches
0001–0004 applied and phase-4 options built in. A small v5.8 addition
exports /proc/handshake_holds and /proc/handshake_spinsites so live USB
debug can see per-class hold times and spin sites while a game runs.

Default bootargs (Handshake policy ON, including defer=1):

  console=ttyS0,115200 console=tty0 earlycon=uart8250,mmio32,0x05000000 fbcon=map:0
  handshake_sched=1
  handshake_sched.timekeeper=1
  handshake_sched.local_timers=1
  handshake_sched.defer=1
  handshake_sched.futex=2
  handshake_sched.futex_exit=1
  handshake_sched.futex_nophash=1
  handshake_sched.futex_rescue_us=1500
  handshake_sched.tty_output=1

Falling back at boot (no rebuild)
---------------------------------
The boot partition also has boot-fallback.scr. To run stock Linux
scheduling on the same v5.8 kernel:

  1. Open the HANDSHAKEOS FAT volume on a PC.
  2. Rename boot.scr to boot-hs.scr (keep a copy).
  3. Copy boot-fallback.scr to boot.scr.
  4. Eject and boot the handheld.

boot-fallback.scr uses:

  handshake_sched=off handshake_sched.timekeeper=0 handshake_sched.local_timers=0
  handshake_sched.defer=0 handshake_sched.futex=0 handshake_sched.futex_exit=0
  handshake_sched.futex_nophash=0 handshake_sched.tty_output=0
  handshake_sched.futex_rescue_us=0

You can also edit boot.cmd and turn a single switch off. Putting
handshake_sched=off alone returns the stock scheduler; the other =0
knobs disable the remaining Handshake paths. /proc/handshake_*
counters stay readable either way.

USB debug
---------
The composite gadget exposes CDC-ACM (serial) and the HSROMS
mass-storage LUN together. ACM is up from the boot menu onward so you
can pull data while a game runs. The LUN is only backed by the HSROMS
partition in USB MODE; it is empty otherwise so /mnt/hsroms can stay
mounted.

Windows: a COM port appears. Then, from cmd.exe, PowerShell, or WSL:

  hsdebug --port COMx --log file.csv --interval 1s

Or omit --port and --log; hsdebug auto-detects the port and writes
under handshake\_ops\device-logs\. After you finish playing:

  hsdebug --summarize file.csv

A copy of hsdebug.exe and HSDEBUG.md is on the HANDSHAKEOS volume.
The debug service is read-only (no flash, write, or power-off commands)
and a fault there is logged to HANDSHAKE-BOOT.log and returns to the
boot screen; it does not power the unit off.
